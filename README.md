# 科研经费拨款核对（Flask + Docker Compose）

上传拨款表、归属表、归口表三份 CSV，按**拨款日**做两层内连接，核算各统计单位的
实际合计与实际入表次数，并列出漏计、多计的单号。

新增**分包下发**：同一批三份 CSV 可拆成互不关联的若干包（每笔拨款只进一包），
下载一个 ZIP，每包各含三份 CSV，可交给不同小组在核对页单独重跑，
结果与整批一致。

```

├── requirements.txt

```

## 启动方式

### Docker Compose（交付方式）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

容器以非 root 用户运行 gunicorn（2 worker × 4 线程），带健康检查。
停止：`docker compose down`。

### 无 Docker 时本地运行

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
gunicorn --bind 0.0.0.0:8000 app.web:app     # 或 flask --app app.web run
```

## 输入格式（UTF-8，首行表头，列顺序固定）

| 文件 | 列 |
|---|---|
| 拨款表 | `单号, 项目号, 拨款日, 金额_分` |
| 归属表 | `行号, 项目号, 学院码, 起日, 止日` |
| 归口表 | `行号, 学院码, 统计单位, 起日, 止日` |

- 日期 `YYYY-MM-DD`；有效期为 **[起日, 止日)**，含起日、不含止日。
- 金额单位为分、非负整数；单号与两表行号各自唯一（违反即整次退回）。
- 外键不存在（如项目号在归属表无任何行）不算输入错误，按漏计处理。
- 归属表 / 归口表允许**只有表头**（空底表）：语义等于没有源行，
  拨款按漏计处理，断裂层判断与有数据时一致（分包重跑依赖此行为）；
  拨款表只有表头仍是输入错误。

## 核对规则

一条完整匹配路径 = 一条拨款日有效的归属行 + 一条该归属学院下拨款日有效的归口行。

1. **第一层（归属层）**：`项目号` 相等且拨款日落入归属有效期。命中 0 行 →
   漏计，断在**归属层**。
2. **第二层（归口层）**：对每条命中归属行的`学院码`，找拨款日有效的归口行。
   全部学院都无有效归口 → 漏计，断在**归口层**（页面注明已命中几条归属）。
3. 完整路径数 = **实际入表次数**：0 为漏计，1 为正常，>1 为多计。
4. **同一统计单位的不同匹配路径分别计入**，金额按路径数倍乘。
5. 多计页面给出两条匹配路径示例，各自标出归属表行号与归口表行号，
   并按统计单位列出路径数分布。

### 为什么不枚举匹配路径也能算合计与次数

设某笔拨款在学院 c 命中 `n_attr(c)` 条归属行、该学院拨款日有 `n_jur(c)` 条归口行，
归口行 j 指向统计单位 u，则：

```
该归口行对应的路径数 = n_attr(c)
单位 u 的入表次数  += n_attr(c)
单位 u 的合计      += n_attr(c) × 金额
```

引擎按“学院 → 有效归口行”聚合，只做加法与乘法，**不构造归属×归口的笛卡尔积**。
时间复杂度只与命中的归属行、归口行数量有关，与路径总数（乘积）无关。
自测中 600 归属 × 800 归口 = 48 万条路径，引擎仅构造 2 个用于页面展示的
示例路径对象即完成全部合计与次数计算。

## 分包下发（/split）

首页第二个表单上传**原来的三份 CSV**，后端把整批拆成若干包，返回
`分包结果.zip`：

```
分包结果.zip
├── 分包清单.csv            # 每笔拨款属于哪一包（包,单号,项目号,拨款日,金额_分）
├── 第01包/
│   ├── 拨款表.csv           # 该包的全部拨款
│   ├── 归属表.csv           # 这些拨款在各自拨款日命中的全部归属行
│   └── 归口表.csv           # 经命中归属行（同学院、拨款日有效）命中的全部归口行
├── 第02包/ ...
```

### 分包规则（实现）

1. 逐笔计算命中源行：归属行按"项目号 + 拨款日 ∈ [起日, 止日)"，
   归口行按命中归属行的学院去重后查"学院码 + 拨款日 ∈ 有效期"。
   **只列出源行本身，不展开完整匹配路径**（不构造归属×归口组合）。
2. 共用任一条源行（归属行或归口行）的拨款用**并查集**合并；
   间接共用经连通分量自然传递（A 与 B 共用归属行、B 与 C 共用归口行
   ⇒ A/B/C 同包）。互不关联的拨款落在不同分量，自然分开。
3. 每包内容 = 包内全部拨款 + 各笔命中源行的并集（去重，保持原文件行序）；
   包号按组内首笔拨款的原始顺序分配，同一输入结果稳定。
4. 某张底表没有命中行时仍写出**只有表头**的 CSV（空底表），
   重跑后漏计断层判断与整批一致。
5. 任一上传文件有误（与核对同一套校验）：HTTP 400，逐条列出
   文件 + 行号 + 原因，**整批不出包**，不产生任何部分结果。

### 为什么各包重跑与整批一致

某行是否被某笔拨款命中，只取决于"项目号 / 学院码 + 拨款日是否落入有效期"，
与同一份 CSV 里还有哪些其他行无关。包内包含了每笔拨款在整批中命中的
全部源行；其他拨款带进来的额外源行，对该拨款要么拨款日不在有效期内、
要么键不匹配，不会多命中。因此：

- 逐笔入表次数、漏计断层（归属层 / 归口层）、多计证据（单位分布与示例路径）
  都与整批一致；
- 各包的统计单位合计相加等于整批合计（拨款被划分，且逐笔贡献相同）。

以上两条由自测第 [7]/[10] 节对每一批构造数据和样例数据逐包验证。

## 错误处理（整次退回）

任一文件存在问题时，本次核对 / 分包不产生任何部分结果，HTTP 400 进入错误页，
逐条列出**文件名 + CSV 物理行号 + 原因**，三个文件的错误一次性全部返回。
覆盖：表头不符、列数不符、日期格式、金额非整数/负数、必填为空、
单号或行号重复、有效期起日不早于止日、空文件、非 UTF-8、NUL 字节、缺传文件。

## 自测

```bash
python3 -I tests/test_reconcile.py     # 需先 pip install Flask
```

脚本与数据目录分离并以 `-I` 隔离模式运行，避免从数据目录加载同名模块。

### 实测结果（本机，Python 3.11 + Flask 3.0.3）

- 118 条断言全部通过（无 Flask 的隔离模式下 79 条，网页段自动跳过），覆盖：
  - 基础两层连接、漏计（归属层 / 归口层）、多计、菱形连接汇入同一单位分别计入；
  - 半开区间边界：两层各自验证起日当天命中、止日当天失效；
  - **重叠归属**：同项目 3 条并行归属 → 3 条路径、金额按路径倍乘；
  - **大量重复匹配**：600 × 800 = 480,000 条路径，次数与合计精确，耗时约 22ms，
    全程只生成 2 个示例路径对象；
  - 13 类输入校验，均带文件与行号，多文件错误一次返回；
  - **分包规则**：跨日期共用源行同包（含"共用归属行但归口行不重叠"）、
    间接共用传递同包、互不关联分开、每笔只进一包、空底表自成一包；
  - **各包重跑一致**：逐笔次数与状态、漏计断层、多计证据（单位分布与示例路径）
    与整批完全一致，各包单位金额相加 = 整批（构造数据 3,200 分、样例 3,800,000 分）；
  - **空底表**：归属 / 归口表只有表头可解析，归属层 / 归口层漏计判断保留，
    完全空文件（连表头都没有）仍报错；
  - **分包不展开路径**：480,000 条潜在路径下分包 + 打 ZIP 约 30ms，
    包内只有 1,400 条源行；
  - Flask 端到端：/check 正常上传 200、错误 400 整次退回、缺文件 400；
    /split 返回 application/zip 附件、ZIP 结构（每包三份 CSV + 分包清单）、
    CSV 带 BOM、出错 400"整批未出包"。
- 另用 gunicorn 实起服务、curl 真实上传验证：
  - /check 上传样例三表：HTTP 200，多计次数 2/3/2/4、总入表 11 次、
    总合计 38,000.00 元，与手工核算一致；错误上传 400 且定位"拨款表 第 2 行"；
  - /split 上传样例三表：HTTP 200 下载 `分包结果.zip`，拆成 4 包
    （G001/G002/G003/G006 共用归口行同包，G004/G005 归属层断裂各自空底表单列，
    G007 归口层断裂单列）；逐包解出后真实 HTTP 回传 /check 全部 200，
    逐笔次数、单位金额相加（U1=1,800,000、U2=2,000,000、总计 3,800,000 分）
    与整批一致；
  - /split 上传跨日期共用源行 + 空底表演示数据（9 笔）：拆成 6 包，
    GA1(02-01)/GA2(06-01) 跨日期共用归属行同包且 GA2 多计 ×2 证据保留，
    GB1—GB2—GB3 间接共用同包，GC1 包两张底表只有表头仍判归属层漏计，
    GD1 包归口表只有表头仍判归口层漏计；
  - /split 上传错误文件：HTTP 400，提示"整批未出包"并定位"拨款表 第 2 行"。

## 未完成项 / 已知限制

1. 交付环境没有 Docker daemon，`docker compose up` 未在本机实跑；
   已通过 compose YAML 语法校验，并用同版本 gunicorn 做了等价的本地实跑验证。
2. 结果仅在当次页面展示 / 当次下载，未做持久化、历史记录或报表导出（如 Excel）；
   分包 ZIP 由上传数据实时生成，服务器不留存。
3. 文件全量读入内存，上传上限 16MB；未实现流式解析。
4. 有效期匹配为按项目/学院线性扫描；若单项目归属行或单学院归口行极多，
   可进一步改为按日期排序 + 二分查找（区间树）。
5. 金额只接受整数分，不接受浮点"元"；无登录鉴权与多用户隔离。
6. ZIP 内文件夹与 CSV 使用中文名（UTF-8 标志位），现代解压工具与
   Excel 均可正常打开；个别老旧解压软件可能显示乱码文件名（内容不受影响）。
7. 自测为独立断言脚本，未引入 pytest，前端无浏览器自动化测试。
